# Phase 04M baseline audit

Baseline: commit `ce53d80` (`new UI again`). The working tree was clean before this phase. The existing production build was profiled and captured before source changes; see `baseline/profile.json` and its forward/reverse JPEGs.

1. **Progress:** `useSectionProgress` already owns the shared, animation-frame-throttled scroll/resize feed. HeroAquarium independently derived its exit fraction from the live Hero rectangle. It mapped that fraction into two CSS values: depth starting at 40%, and edge travel starting at 30%. No additional scroll controller is necessary.
2. **Hero lifecycle:** the old scene effect depended on its `animate` flag, which combined enablement, scene readiness, intersection, document visibility, preferences, and failure. Turning that flag off disposed the renderer. IntersectionObserver thresholds also drove React state and the App handoff latch. Time was retained, but a hidden tab or complete exit could reconstruct the scene on return.
3. **Underwater backdrop:** the existing fixed AquariumDive canvas is already behind the portfolio. Its established palette, lighting, filtering, and absorption remain useful. App parks its renderer while Hero is active and resumes it at the old 10% remaining-Hero threshold. That is much later than the visible crossing needs.
4. **Old mask:** a two-opacity SVG alpha mask retained the upper scene and uncovered the lower backdrop. Its current polarity was correct. Its 220%-height texture, percentage mask positioning, scaled Hero host, and separately positioned highlight did not share one physical boundary.
5. **Competing timing:** the old surface CSS values were scrubbed without transitions, but the effects used separate remappings rather than a common timeline. The backdrop has existing 800ms appearance/theme transitions. Those remain outside the new surface timeline; none of the new scrubbed properties has a CSS transition.
6. **Phase 04L:** arrival owns the fixed Hero reveal, `--arrival-progress`, the arrival water wrapper, scroll landing, and Navbar docking. A surface layer can become viewport-held only after portfolio unlock. Arrival geometry and scroll ownership must remain intact.
7. **Content:** the headline is real DOM; Hero entry typography defers to Phase 04L. About owns its reveal, typography, and section choreography separately. Neither should be a surface timeline target.
8. **Renderer overlap:** the old handoff briefly ran both scenes near the end of Hero exit. The replacement needs overlap while both worlds are visible, followed by zero Hero draws after submerging. Nearby canvas retention should be separate from active rendering.
9. **Preferences:** Lite and reduced motion already select the Hero poster. The old reduced path still used a late binary mask change. Reduced motion should instead keep normal document scrolling with no held environment, camera approach, clipping, or optical strip.
10. **Structural discontinuity:** the mask was attached to a Hero environment that itself left with the document. The crossing was therefore compressed into an already departing rectangle. Uniform scale and a bright band could not establish a continuous space. The baseline 45% frame shows both that detached band and the straight section boundary.

The implementation uses the installed GSAP core, timeline, React, performance, plugin, and ScrollTrigger guidance. The ScrollTrigger audit supported reusing the existing feed rather than registering another controller. Ponytail guided reuse of the existing scenes, posters, observers, and dependencies. UI-UX Pro Max's local motion/accessibility guidance was consulted. No installed Impeccable SKILL.md was found in the available skill roots or workspace; it was not claimed or installed.
